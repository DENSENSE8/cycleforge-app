## 4. First principles (grounding — cite P# in code comments)

Sources: NN/g Progressive Disclosure · NN/g Slider rules of thumb · NN/g *Negative Impact of Mobile-First on Desktop* (content dispersion, 2023) · Linear Display options · Material 3 button emphasis · Material discrete sliders · Eisenhower matrix · Gorgias order management · Notion projects/docs · Wroblewski *Mobile First* / MDN (mobile first = progressive enhancement).

- **P1** What is on screen says it is important; two disclosure levels max. Row = WHAT / WHEN+STATE (due far left, status right of it) / WHO+WHERE. No field labels: the value and its glyph are the label. Secondary prose → hover/record.
- **P2** One filled primary per region; repeated verbs are tonal.
- **P3** Group by and Order by are separate, remembered controls; urgency = time, importance = Urgent or customer waiting.
- **P4** Groups = whitespace + hairline; highlights inset from dividers.
- **P5** Exact values (dates) get exact controls; sliders only for few coarse stops — dots, snap, flat press face, keyboard-only focus ring.
- **P6** Reference, never copy: docs name live records; charts derive from data; comments anchor to text. Docs read inline (M3).
- **P7** The ticket logs what was sent (structured), picked by recognition from the `+`.
- **Mobile-first method (M1):** priority spec per surface (level 1 vs level 2) written first → phone composition → desktop as enhancement (density, panes, keyboard, hover), never a stretched phone layout (NN/g content dispersion). Validate: top-5 verb time-on-task phone vs desk, ≥44px tap audit at 390px, contrast audit both themes, `parityGaps('home') = []`.
