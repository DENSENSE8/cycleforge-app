# `/search` → station port — executable handoff

## 1. The ruling

`/search?sel=` stops being a hand-assembled preview surface and becomes the **same station tree Unbox mounts**, in `stance="preview"`: `StationScanPaneHost > StationPanelRoot(surface="card") > [StationContextBar | StationWorkbench] + StationDisplaysPushStack`, already generalised as `src/components/station/entity/EntityStationPane.tsx`. Status is gone from the centre in both halves — stepper and audit rows live on the right-edge `timeline` leaf (this is already true in code; do not re-litigate or re-add it). The left rail keeps `SidebarRecentRailBase` — mounting the generic shell with a domain row type **is** the sanctioned pattern (six non-receiving rails do it); `RecentActivityRailBase`/`ReceivingFeedRail` are receiving's *preset* at the same layer and are hard-typed `ReceivingLineRow` → `/api/receiving-lines`, so forcing a `SearchRecentEntry` through them would fabricate a fake receiving row — the very fork the ruling exists to prevent.
