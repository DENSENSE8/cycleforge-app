**Auth floor.** `withAuth` costs about 300 ms per request on this lane. The
pre-existing `/api/settings?page=nav` measures 620–670 ms. Each `tenantQuery` is
4 Neon round trips of about 90 ms each (BEGIN, set_config, statement, COMMIT).
Read paths in this contract use `tenantQueryOneTrip` (`src/lib/tenancy/db.ts`), which
sends the GUC and the statement as one simple-protocol message. That change took
`/api/nav/context` from 661 to 376 ms p50. The `withAuth` session lookup is the
remaining cost. Another session owns it, and it is outside this contract.

- **Free text:** worst p95 188 ms (bose 164/175, guitar hero 148/171, bsoe 159/188,

The free-text budget (p95 < 400 ms) is met in-process. The exact budget

Why these moved:

- **Forced RLS disables index conditions on non-leakproof operators** (enum `=`,
  jsonb `->>`, `COALESCE`, `lower()`, `LIKE`). The fixes:
  - stored generated columns `station_activity_logs.order_row_id` / `ext_order_id`
    with org-led partial indexes (`perf_01`), after which the old jsonb expression
    indexes were dropped (`perf_02`);
  - org-led entity indexes on `work_assignments` and `documents` (`perf_03`, `perf_04`);
  - `COALESCE` → `CASE`, and the `lower(entity_type)` wrapper removed.
- **queue-counts** is now one statement with single-flight, which removes the two
  concurrent 27.5 s cold misses.
- **Correctness fixes:**
  - The `/api/orders` cache key now includes every parsed field plus `limit` and
    `cursor`. `limit=3` returns 3 rows, and the cursor advances.
  - To ship uses one predicate (`sqlOrderInWarehouseToShip`) across the list,
    queue-counts, desk-counts, pack placement and facets. The old 38 vs 406 split is
    gone. The 367 orders with no shipment belong to the Labels queue.
  - The `/shipping/orders` first paint is now seeded in-process. `serverSelfFetch`
    resolves its origin from the request, so there is no longer a silent 401.

## Incidents and hazards during this session

- **Read-only window, 11:17–11:27 PDT.** A Phase 0 scout ran psql on the `.env`
  **pooler** DSN with a session-level `SET default_transaction_read_only=on`. Under
  PgBouncer transaction pooling, a session SET sticks to the server backend, so the
  lane's pool picked up read-only backends. The result was 136
  `cannot execute INSERT in a read-only transaction` errors, including `/api/auth/qr/begin`
  and sign-in 500s. It cleared when PgBouncer recycled the backends. A second scout's
  `BEGIN READ ONLY` plus a non-LOCAL `SET enable_seqscan` on the pooler was the same
  pattern, though transaction-scoped. Commit `0539ad62c` ("Neon branch read-only, quota
  lock suspected") and `docs/HANDOFF-next-session.md:35-40` misattribute this; the
  branch has no read-only setting (`pg_db_role_setting` is empty for it, and owner and
  app_tenant writes succeed). Rule adopted for all agents: use the UNPOOLED DSN only,
  with transaction-scoped `BEGIN READ ONLY … ROLLBACK`, and never a session-level SET.
- **`node_modules` broken at 12:33.** A concurrent session ran pnpm from
  `/tmp/v1-clean-wt` with a shared store, which re-pointed this worktree's
  `node_modules/{tsx,next,pg,…}` at a directory that no longer exists. It was repaired
  with `pnpm install --offline --frozen-lockfile`.
- **Sign-in 500 until ~13:00.** A concurrent session's uncommitted `session.ts` read
  `staff_sessions.credential` before its migration was applied. That session has since
  landed it.
- **Dev-server restarts** (memory threshold at ~4 GB heap, `next.config.ts` edits)
  drop in-flight requests. The probe now records them as transport FAILs and waits.
