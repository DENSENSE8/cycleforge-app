## What changed

1. **Sidebar fan-out split** — `SidebarContextPanel` statically imported ~20
   feature sidebar panels, dragging every feature area's component graph into
   the shared shell bundle on every route. Each panel is now a `next/dynamic`
   chunk loaded per route key. This was the single largest lever (−1 MB gz on
   /signin).
2. **Shell provider diet** — `CommandBar` (cmdk), `GlobalDesktopSkuScanner`,
   `ReceivingPhoneBridgeMount`, `DashboardSidebar`, and the assistant dock body
   are `next/dynamic`; ActivityInbox seed fetches and the StaffColors warmup
   defer to idle (`useIdleReady`).
3. **Print-stack altitude fixes** — the bwip-js barcode engine (~250 KB gz) was
   reachable from station/dashboard bundles through light helpers stranded in
   heavy modules: `receivingLabelTypeDisplay` (→ `lib/receiving/receiving-type-display`),
   `escapeLabelHtml` (→ `lib/print/labelHtml`), and static `printLabel` /
   `labelCommands` imports in the five `print*Label` entries (now lazy inside
   the print actions). Printing behavior is unchanged; the engine loads on the
   first actual print.
4. **Server-only DB fence** — `src/lib/db.ts` now carries `import 'server-only'`.
   The probe builds surfaced and fixed four live client-side DB-driver leaks
   (photos image-types, stations barrel `surface-resolver`, support tickets
   scan/ref helpers, channel-allocation `ready-queue`, claim seller-message
   refs) — each fixed by splitting a light client-safe module the heavy module
   re-exports. Any future client path to the DB is a build error naming the
   exact import chain.
5. **Route loading UI** — `loading.tsx` (shared `RouteLoading` DS primitive) on
   Tier-1/2 routes + the mobile shell groups.
6. **Image hygiene** — `loading="lazy"` / `decoding="async"` / alt fixes across
   19 hot-path files (NAS photo surfaces are auth-proxied, so raw `<img>` stays;
   `next/image` would 401 in the optimizer — see LIGHTHOUSE.md).

## Verdict vs targets

- **Passing Perf ≥70:** /signin 78, /packer 77, /m/receive 77, /m/scan 76, /m/home 71.
- **At 67–69 (from 62–65):** /dashboard, /unbox, /triage, /test, /search — these
  are the data-heavy workbenches whose LCP waits on client-side data fetches
  after hydration; the remaining gap is architectural (RSC/streaming of the
  first collection payload), not bundle weight.
- **TBT ≤ 600ms:** every route now 22–158 ms (baseline 208–284). **CLS ≤ 0.1:**
  ~0 everywhere. **A11y ≥ 90** (93–95) and **BP ≥ 90** (96): pass. **SEO ≥ 80**
  on public /signin: 91.

## Remaining levers (deferred — see Compound opportunities in the worklog)

- Stream the first collection payload (RSC or route-handler preload) on
  /dashboard, /unbox, /triage, /search so LCP stops waiting for
  hydrate-then-fetch. Highest-leverage next step for the 67–69 group.
- Station bundles still ~1 MB gz: the unified station graph (~1,000 modules)
  is a monolith; splitting the station workspace tabs would need the
  station-block registry work (Tier-3 / ask-first).
- Split inactive theme palettes out of the inline `<head>` CSS (~19 KB of
  32 KB inline).
