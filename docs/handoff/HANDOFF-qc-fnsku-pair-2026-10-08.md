Pairing is a **catalog fact** (`fba_fnskus.sku_catalog_id`), not a per-unit one:

- **Line open** → `useQcFnskuCandidates` fetches every active FNSKU paired to the line's `sku_catalog_id` (indexed; one request, shared React Query cache) and preloads the FNSKU label renderer (bwip-js).
- **Pass / reprint press** → `resolveQcFnsku(candidates, unitGrade)`:
  - exactly one grade-matched candidate → its sticker prints via `printFnskuLabelJob(face, 1)` right beside `printProductLabel`, no request in front of either;
  - duplicates, grade mismatch, `REFURBISHED`/`PARTS` (no FBA words), or nothing paired → the chip's popover decides.
- **The one press request** (`POST /api/qc/units/[id]/print-pass`) now carries `fnsku`; the outbox job appends the fnsku ledger row (`label_print_jobs`, `templateId 'fba_fnsku'`, idempotent on `${client_event_id}:fnsku`).
- **Pair (popover confirm)** → `POST /api/qc/fnsku-pair` sets `fba_fnskus.sku_catalog_id`; every later pass of that SKU auto-prints. Steal-guard: pairing an FNSKU already bound to another catalog row answers 409.
