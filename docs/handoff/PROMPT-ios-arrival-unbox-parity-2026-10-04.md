## Known defects to fix (operator report, ground truth)

1. **Carrier barcodes refused.** Scanning a carrier label at Inbound said "Not
   received · Nothing arrives under a product label". Cause, reproduced with
   the web router: `routeScan` treats these as SKU or bin, and
   `arrivalScanIntent` refuses them on the phone before the server's last-8
   match runs:
   - USPS `420`+ZIP+tracking in one barcode (`420900019361289711068322544977` → sku)
   - FedEx Ground `96…` (`96119123456789012345678` → sku)
   - Amazon `TBA…` (→ bin)

   The web has the same bug.
2. **Repeat gate too strict.** A re-scan said "Already scanned — not sent
   again" even though the first scan was refused locally and never sent
   (`ScanStation.swift:218`).
3. **Scanned package unreachable.** There is no way to open the tracking number
   just scanned, and a refused package never reaches Unbox.
4. **Unbox can't be sorted or searched.** It has no Sort by and no search;
   long queues are unusable.

## Highest-value next steps, in order

1. **Scan classification parity and the carrier-envelope fix**, in the web lib
   first, ported with fixtures from real production scan values. Without this,
   Arrival doesn't work.
2. **The scanned package is always reachable**: tappable latest-result card
   and a Recent list (the web's arrival tape) on both surfaces.
3. **Generated design tokens and shell chrome**: the app header, switcher,
   scan button and spacing all come from web tokens. Every later screen
   inherits this, so it pays back on every screen.
4. **Pixel parity of Scan → Pair → Label photo → Unbox** against the web, with
   a diff score per screen.
5. **Unbox Sort by and search**, server-side, on both surfaces.
6. **Parity guard in CI-less form**: one command that regenerates every
   fixture and token file and fails when the web and the app disagree. The
   operator runs it before any deploy.
